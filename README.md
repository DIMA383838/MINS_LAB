# Лабораторная работа №2: Паттерны проектирования

## Что сделали
Взяли программу для автосервиса из первой лабораторной и добавили в неё 3 паттерна проектирования.

## Какие паттерны использовали

### 1. State (Состояние)
**Зачем:** Раньше у заявки был просто флаг "выполнено/не выполнено". Это плохо, потому что заявка может быть в разных статусах.

**Как сделали:**
- Добавили статусы: **НОВАЯ → В РАБОТЕ → ВЫПОЛНЕНА → ОТМЕНЕНА**
- Каждый статус — отдельный класс
- Нельзя отменить выполненную заявку или вернуть готовую обратно в работу
- **Файлы:** `NewState.java`, `InProgressState.java`, `CompletedState.java`, `CancelledState.java`

### 2. Strategy (Стратегия)
**Зачем:** Раньше цена услуги была всегда одинаковая. В жизни бывают скидки и наценки.

**Как сделали:**
- Можно выбрать способ расчета цены при создании заявки
- Сделали 3 стратегии: обычная, скидка 5% для постоянных, наценка 20% за срочность
- **Файлы:** `DiscountStrategy.java`, `NoDiscountStrategy.java`, `RegularClientDiscountStrategy.java`, `UrgentMarkupStrategy.java`

### 3. Observer (Наблюдатель)
**Зачем:** Когда меняется статус заявки, хорошо бы кого-то уведомлять (логгер, клиента).

**Как сделали:**
- Заявка не знает, кто её слушает, просто оповещает всех подписчиков
- Сделали два наблюдателя: логирование в консоль и уведомление клиента
- **Файлы:** `AppointmentObserver.java`, `LoggerObserver.java`, `ClientNotifierObserver.java`

## Что изменилось в программе
В меню появились новые пункты:
- Выбор типа скидки при создании заявки
- Отдельные пункты для изменения статуса и отмены заявки
- При смене статуса автоматически пишется лог и "приходит уведомление клиенту"


## Состав проекта
- `model/` — модели данных (клиент, машина, услуга, заявка)
- `model/status/` — классы статусов для паттерна State
- `service/` — сервисы для работы с логикой
- `service/discount/` — стратегии скидок
- `observer/` — наблюдатели
- `repository/` — репозитории для хранения данных (без изменений)
- `AutoServiceConsoleApp.java` — консольное меню
